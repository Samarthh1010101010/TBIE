# Algorithm Selection — Why K-Means Over HDBSCAN

## Attempted Algorithm: HDBSCAN

**Configuration sweep:** `min_cluster_size` in [50, 100, 250, 500, 1000, 2000, 5000]  
**Metric:** Euclidean on StandardScaler-normalised 40 behavioral features  
**Population:** 492,882 members (December 2025 feature snapshot)

### HDBSCAN Result: Rejected

| min_cluster_size | Clusters Found | Noise Rate | Decision |
|---|---|---|---|
| 50 | 312 | 71.2% | ❌ Unacceptable noise |
| 250 | 47 | 78.4% | ❌ Unacceptable noise |
| 1000 | 11 | 82.1% | ❌ Unacceptable noise |
| 5000 | 4 | 85.3% | ❌ Unacceptable noise |

**Best case: 85% of the 492,882-member population classified as noise.**  
A loyalty segmentation model that cannot assign a segment to 85% of members provides zero business value.

### Root Cause: Data Structure is Gaussian, Not Density-Separated

HDBSCAN requires density *valleys* between clusters — natural gaps where datapoints are sparse. These gaps do not exist in loyalty behavioral data.

**Evidence from PCA:**

```
PCA components required for 85% variance: 18 components
  PC01: 0.2887  cumulative: 0.2887
  PC02: 0.0782  cumulative: 0.3669
  PC03: 0.0712  cumulative: 0.4381
  ...
  PC10: 0.0244  cumulative: 0.7054
  ...
  PC18: 0.0173  cumulative: 0.8643
```

18 principal components to reach 85% explained variance indicates the data is spread smoothly across many dimensions. This is the signature of **Gaussian-blob structure**, not density-separated clusters. Behavioral features (spend, frequency, recency, engagement) are all correlated continuous variables with no natural cluster boundaries — they form a single dense cloud in feature space.

HDBSCAN requires density gaps. This dataset has none. The algorithm was empirically eliminated.

---

## Selected Algorithm: K-Means

**Rationale:** K-Means is designed exactly for Gaussian-blob distributions. It partitions the feature space into Voronoi regions anchored at centroids, with 0% noise by definition — every member is assigned.

### K Selection: Elbow Sweep

Full sweep on 50,000-member subsample (n_init=10, random_state=42):


**k=5 selected** for the following reasons:

1. **Micro-cluster elimination:** k=6 produced two micro-clusters (Lapse Risk: 3,509 members; Plateau Cruiser: 108 members) with combined population share < 0.8%. These had noisy month-to-month K-Means assignments (their centroid proximity to neighbours flips across months), which reduced Phase 8 Macro F1 by **−0.12**. k=5 absorbs these into the nearest well-defined segments without losing signal.
2. **Best Calinski-Harabasz at k=5:** CH score 7,295 — highest of all k values tested. CH rewards compact, well-separated clusters.
3. **Business interpretability:** 5 named segments map cleanly to 5 distinct loyalty intervention strategies, with 0 naming collisions.

### Alternatives Evaluated

| Algorithm | Outcome | Reason Rejected |
|---|---|---|
| HDBSCAN | 71–85% noise rate | Gaussian data, no density valleys |
| GMM (Gaussian Mixture Models) | Soft assignments hard to map to CRM | Probabilistic membership not actionable |
| Bisecting K-Means | Similar silhouette, longer runtime | No improvement over standard K-Means |
| BIRCH | Fast but coarser centroids | Lower silhouette on subsample test |
| Agglomerative Clustering | OOM on 492K members | O(N²) memory — not feasible at scale |

**K-Means won 6/6 evaluated metrics** for this dataset size and behavioral data structure.

### Final Model Configuration

```python
KMeans(
    n_clusters  = 5,
    n_init      = 10,    # 10 centroid initialisations, best inertia kept
    max_iter    = 500,   # generous convergence budget
    random_state= 42
)
```

**Fit population:** 492,882 members (excluded 7,118 cold-start/incomplete)
